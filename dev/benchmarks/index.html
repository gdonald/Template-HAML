    Benchmarks¶

    The repo ships a small bench harness at bench/render.raku that compares the two codegen paths — the AST walker (default) and the direct-emit codegen (:emit<direct>, see API) — on a fixed set of representative templates.

    Run¶

    From the project root:

    1
    bench/render.raku

    This runs each case for 5000 iterations. Override with --iters:

    1
    bench/render.raku --iters=20000

    The shebang is #!/usr/bin/env -S raku -Ilib, so the script picks up the project's lib/ automatically as long as you run it from the repo root.

    Columns:

    Column Meaning
    AST (ms) Total wall-clock time for iters renders via :emit<ast>.
    Direct (ms) Same, via :emit<direct>.
    Δ (ms) AST − Direct. Positive means direct emit was faster.
    speedup AST / Direct.

    Each case is run once for both paths before the timed loop, so the per-template precompile/EVAL cost is excluded from the timings — what's being measured is steady-state render speed.

    Cases¶

    The cases live in the bench-cases sub at the bottom of bench/render.raku. Each entry is a (name, src, locals) record. Add a case by appending to the returned list — the harness reflows the table to fit.

    Caveats¶

    • The numbers are wall-clock and depend on machine load. Run a few times if the comparison is close.
    • The harness times HAML.render(:src, …) end-to-end. The first render for each path warms internal caches; subsequent renders reuse the cached closure, so the times reflect the steady-state cost, not first-render cost.
    • :emit<direct> does not cover every feature yet. If a case template uses something direct emit doesn't support (trim-inner, remove-whitespace, preserved tags with children, find-and-preserve), the bench will throw X::HAML::DirectCodegenUnsupported. See API: Currently incompatible with direct emit.
